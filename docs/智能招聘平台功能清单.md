# 企业级智能招聘平台功能清单

## 1. 文档说明

### 1.1 项目定位

本项目定位调整为围绕招聘业务闭环落地的 **AI Agent 工程化项目**。招聘流程是业务载体，项目重点展示 AI 如何接入真实流程、如何可解释与可追溯、如何结合异步任务、Embedding、RAG、Prompt 版本管理和离线评测，并始终由人类做最终招聘决策。

当前招聘业务闭环覆盖：

> 用人需求 → 审批 → 职位发布 → 人才获取 → 简历筛选 → 面试协作 → 录用审批 → Offer → 入职交接 → 招聘分析

平台强调以下核心原则：

- AI 参与业务流程，但不替代人的最终招聘决策。
- AI 输出必须提供证据、依据、引用或不确定性说明。
- AI 调用、Prompt、模型、异步任务和人工修订均可追踪、可评测、可审计。
- 兼顾招聘效率、候选人体验、数据安全和招聘合规。
- 以单企业招聘平台为演示边界，突出 AI 工程化能力而非多租户商业 ATS。

### 1.2 AI 工程化专项路线

| 编号 | 专项 | 建设目标 | 状态 |
| --- | --- | --- | --- |
| AI-00 | 项目定位与 AI 控制台 | 调整项目定位，新增 AI 控制台一级入口和专项导航骨架 | 进行中 |
| AI-01 | AI 调用日志与任务中心 | 统一观测 AI 调用、OCR、解析、Embedding、推荐和后续 Agent 异步任务 | 计划中 |
| AI-02 | Prompt 模板管理与版本化 | 管理场景化 Prompt、发布版本、历史回滚和结构化输出约束 | 计划中 |
| AI-03 | 企业招聘知识库 RAG | 上传招聘制度、岗位标准、面试评分、Offer 规则和沟通话术，检索结果带引用 | 计划中 |
| AI-04 | 候选人问答 Agent | 汇总候选人全链路信息和知识库证据，回答招聘专员问题但不自动决策 | 计划中 |
| AI-05 | AI 评测与错误案例库 | 用固定合成样本比较模型和 Prompt 版本，沉淀错误类型和质量指标 | 计划中 |

## 4. 核心业务规则

1. 招聘需求未完成必要审批时，不允许正式开放关联职位。
2. 候选人档案与应聘记录分离：同一候选人可以应聘多个职位。
3. 候选人每次阶段变化必须记录操作人、时间、来源状态、目标状态和原因。
4. AI 的推荐、评分和报告必须允许人工查看、修改和否决。
5. AI 给出的关键判断应尽可能引用简历、面试记录或企业知识库中的证据。
6. “信息未出现”与“不符合要求”必须明确区分。
7. 面试官只能查看完成当前面试所必需的候选人信息。
8. 多面试官评价默认独立提交，减少相互影响。
9. 薪资、证件、背调和健康等敏感数据采用更严格的字段权限和审计策略。
10. 候选人淘汰、录用和 Offer 决策由授权人员作出，AI 不自动作最终决定。
11. 同一候选人从多个渠道进入系统时，应提示去重并保留来源贡献记录。
12. 所有模板、规则、流程、Prompt 和模型配置应支持版本管理。
13. 历史业务记录应绑定当时生效的规则版本，避免新配置改变历史结论。
14. 候选人数据必须具备授权、保留期限、导出、更正、删除或匿名化机制。
15. 招聘质量闭环只能在合法、授权、最小必要和严格权限控制下关联入职后数据。

## 5. 关键业务状态建议

### 5.1 招聘需求状态

`草稿 → 审批中 → 已批准 → 招聘中 → 已完成`

补充终止状态：`已驳回`、`已撤销`、`已关闭`。

### 5.2 职位状态

`草稿 → 待发布 → 招聘中 → 暂停 → 已关闭`

### 5.3 候选人应聘状态

流程阶段由企业配置，基础状态可包括：

`待筛选 → 初筛 → 测评/笔试 → 一面 → 二面 → HR 面 → 背调 → Offer 审批 → 待签署 → 待入职 → 已入职`

任意适用阶段可进入：`已淘汰`、`候选人撤回`、`转其他职位`、`暂缓`。

### 5.4 Offer 状态

`草稿 → 审批中 → 已批准 → 待发送 → 待签署 → 已接受 → 已入职`

补充终止状态：`审批驳回`、`候选人拒绝`、`已撤回`、`已失效`、`接受后放弃`。

## 7. 推荐实施范围

## 7.1 P0：完整可演示闭环

目标：完成一个可以演示真实招聘主流程的 AI 增强型 ATS。

- 企业、部门、岗位、用户和基础角色。
- 招聘需求和职位管理。
- JD 生成、优化和结构化要求。
- 候选人档案、简历上传与解析。
- 人岗匹配、证据引用、缺失项和面试建议。
- 候选人看板、阶段流转、淘汰、转职位和时间线。
- 面试题库、面试方案、结构化评分和面试报告。
- 基础工作台、待办、提醒和招聘漏斗。
- 基础权限、操作日志和 AI 人工修订。

建议演示主线：

> 用人经理创建需求 → HR 创建职位并使用 AI 优化 JD → 导入简历 → AI 匹配并解释 → HR 推进候选人 → 安排并完成结构化面试 → 生成面试报告 → 查看招聘漏斗

## 7.2 P1：真实企业协作能力

目标：让系统不仅能演示，还能够覆盖中小团队的日常招聘协作。

- 编制和预算管理。
- 招聘需求、Offer 审批工作流。
- 字段级和数据范围权限。
- 候选人去重、档案合并和人才库。
- 面试日程、候选人自助预约和通知。
- 多面试官独立评价和反馈催办。
- Offer 模板、薪资校验、发送和状态跟踪。
- 候选人门户、材料收集和入职确认。
- 招聘渠道、消息模板和更多分析报表。
- 企业知识库、Prompt 管理、模型日志和成本统计。
- 数据脱敏、隐私授权和 AI 输入控制。

## 7.3 P2：企业化、平台化与智能化

目标：支持多企业、复杂组织和规模化运营。

- 多租户、套餐、配额、功能开关和租户隔离。
- SSO、多因素认证和完整数据权限体系。
- HRIS、招聘网站、日历、会议、企微/钉钉、电子签和背调集成。
- 可配置条件工作流和业务自动化规则。
- 在线测评、背调和高级人才关系管理。
- 招聘质量闭环、公平性分析和合规规则库。
- AI 模型路由、灰度、降级、链路追踪和评测平台。
- 异常访问检测、数据生命周期和灾难恢复。
- 大规模简历处理、搜索和异步任务调度。
